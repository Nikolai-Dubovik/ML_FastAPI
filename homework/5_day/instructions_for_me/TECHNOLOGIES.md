## 📏 StandardScaler — масштабирование числовых признаков

Числовые признаки живут в разных масштабах: `monthly_fee` ~ десятки,
`account_age_months` ~ до сотни, `autopay_enabled` — 0/1. Логистическая
регрессия чувствительна к масштабу: признак с большими значениями получит
незаслуженно большой вес.

**StandardScaler** приводит каждый столбец к среднему 0 и стандартному
отклонению 1:
```
x_scaled = (x - mean) / std
```
`mean` и `std` считаются **только по train** (это делает `fit`), а к test
применяются уже готовые (`transform`) — иначе информация из test «утекла»
бы в обучение.

---

## 🔤 OneHotEncoder — кодирование категориальных признаков

Модель не умеет работать со строками `region="europe"`. **One-hot
кодирование** превращает категорию в набор бинарных столбцов:

| region | → | region_africa | region_america | region_asia | region_europe |
|--------|---|---|---|---|---|
| europe | → | 0 | 0 | 0 | 1 |
| asia   | → | 0 | 0 | 1 | 0 |

```python
OneHotEncoder(handle_unknown="ignore")
```
**`handle_unknown="ignore"`** — важный параметр: если на предсказании
придёт категория, которой не было в train (например, новый регион),
энкодер не упадёт с ошибкой, а закодирует её нулями во всех столбцах.

---

## 🧩 ColumnTransformer — разным колонкам разная обработка

Числовые надо масштабировать, категориальные — кодировать.
**ColumnTransformer** применяет к каждой группе колонок свой трансформер и
склеивает результат в одну матрицу:

```python
preprocessor = ColumnTransformer([
    ("num", StandardScaler(), NUMERIC_FEATURES),        # 6 колонок
    ("cat", OneHotEncoder(handle_unknown="ignore"), CATEGORICAL_FEATURES),  # 3 колонки
])
```
Каждый элемент — кортеж `(имя, трансформер, список_колонок)`. Колонки
выбираются **по именам** — здесь окупаются явные списки признаков из дня 4.
На выходе: 6 масштабированных + 10 one-hot столбцов (4 региона + 3
устройства + 3 способа оплаты) = матрица из 16 признаков.

---

## 🔗 Pipeline — предобработка и модель как один объект

**Pipeline** соединяет шаги в цепочку: выход одного — вход следующего.

```python
pipeline = Pipeline([
    ("preprocessor", preprocessor),                     # ColumnTransformer
    ("classifier", LogisticRegression(max_iter=1000)),
])
pipeline.fit(X_train, y_train)     # обучает И предобработку, И модель
pipeline.predict(X_test)           # сам прогоняет данные через все шаги
```

Зачем это нужно:
- **Нет утечки данных**: `fit` обучает скейлер/энкодер только на train, к
  test автоматически применяется только `transform`;
- **Нельзя забыть шаг**: невозможно случайно подать в модель
  немасштабированные данные;
- **Один объект** — в дне 6 сохраним на диск весь pipeline целиком, и
  предобработка «переедет» вместе с моделью.

---

## 🤖 LogisticRegression — базовый классификатор

Несмотря на слово «регрессия», это модель **классификации**: она
предсказывает вероятность класса 1 (churn) и по порогу 0.5 выдаёт 0 или 1.
Это стандартная **baseline-модель**: простая, быстрая, интерпретируемая —
идеальная отправная точка, с которой потом сравнивают модели посложнее.

```python
LogisticRegression(max_iter=1000)
```
**`max_iter=1000`** — модель обучается итеративным оптимизатором; дефолтных
100 итераций может не хватить до сходимости (sklearn предупредит
`ConvergenceWarning`), поэтому запас.

Паттерн API sklearn одинаков у всех моделей:
- **`fit(X, y)`** — обучение;
- **`predict(X)`** — предсказание классов;
- (в дне 7 добавится `predict_proba(X)` — вероятности).

## 📊 Метрики: accuracy vs f1 — история про дисбаланс

**accuracy** — доля правильных ответов. **f1** — гармоническое среднее
precision (сколько из предсказанных «уйдёт» действительно ушли) и recall
(сколько из реально ушедших модель нашла), считается по классу 1.

Наш реальный результат:

| Метрика | Значение | Как читать |
|---------|----------|------------|
| accuracy | 0.7875 | выглядит неплохо... |
| f1 | 0.0449 | ...но уходящих клиентов модель не находит |

В test 400 клиентов, из них 81 ушёл — а модель предсказала «уйдёт» всего
для 8. Тупая стратегия «всегда отвечай 0» дала бы accuracy 0.7975 — **выше
нашей модели!** При дисбалансе 80/20 accuracy почти не отличает полезную
модель от бесполезной, поэтому задание требует и f1: он считается по
редкому классу и сразу вскрывает проблему. Бороться с ней будем позже
(например, `class_weight="balanced"` поднимает f1 до ≈0.35 ценой accuracy).

```python
from sklearn.metrics import accuracy_score, f1_score
accuracy_score(y_test, y_pred)
f1_score(y_test, y_pred)
```

## 🔗 Где это в API

`POST /model/train` вызывает `train_churn_model(dataset.df)`: сплит из дня
4 → `pipeline.fit` на train → метрики на test → JSON с `accuracy`, `f1` и
размерами выборок. POST (а не GET), потому что обучение **меняет состояние
сервиса** — появляется обученная модель. Если датасет пуст —
`HTTPException(400)` вместо падения.
