## ⚙️ Как будет работать решение

### `models.py` — модель ответа
```python
class PredictionResponseChurn(BaseModel):
    prediction: int                    # 0 — останется, 1 — уйдёт
    probabilities: dict[str, float]    # {"0": 0.9644, "1": 0.0356}
```
Плюс пример запроса для `/docs`: в `FeatureVectorChurn` добавить
`model_config = ConfigDict(json_schema_extra={"example": {...}})` с
реалистичным клиентом — Swagger подставит его в форму запроса.

### `model.py` — функция предсказания
`predict_churn(pipeline, features: list[FeatureVectorChurn])`:
1. собирает DataFrame из `f.model_dump()` **с явным порядком колонок
   `FEATURE_COLUMNS`** — тот же набор и порядок, что при обучении;
2. `pipeline.predict(X)` → классы, `pipeline.predict_proba(X)` →
   вероятности;
3. сопоставляет вероятности классам через `pipeline.classes_` (не
   угадываем порядок колонок в proba!);
4. возвращает список `PredictionResponseChurn`.

### `main.py` — обновлённый эндпоинт
```python
@app.post("/predict")
def predict(features: FeatureVectorChurn | list[FeatureVectorChurn]):
```
- модель не обучена (`model_state is None`) → `HTTPException(400,
  "модель ещё не обучена — вызовите POST /model/train")`;
- одиночный объект оборачивается в список, предсказывается, наружу
  возвращается один `PredictionResponseChurn`; список → список ответов.

Реальные ответы дефолтной логрегрессии (random_state=42):
- «лояльный» клиент (3 года стажа, автоплатёж, 0 неудачных платежей) →

- «рисковый» клиент (2 месяца стажа, 4 неудачных платежа, 8 обращений в

- Список из двух клиентов → список из двух ответов.
- `rm models/churn_model.joblib` + рестарт → `POST /predict` → 400.

## ⚠️ Возможные подводные камни

- **Порядок вероятностей в `predict_proba`** соответствует
  `pipeline.classes_` (у нас `[0, 1]`), а не «сначала 0, потом 1 по
  определению» — сопоставлять явно через zip с `classes_`.
- **Порядок колонок при предсказании**: DataFrame строить с
  `columns=FEATURE_COLUMNS`. ColumnTransformer выбирает колонки по именам,
  но явный порядок — страховка и требование дня 9.
- **JSON-ключи вероятностей** — строки `"0"/"1"` (в JSON ключи объекта
  всегда строки), поэтому `dict[str, float]`.
- **Union-тип входа**: FastAPI сам разберёт, объект пришёл или список;
  важно вернуть ту же форму (один → один, список → список).
- **Низкий f1 дня 5 виден на практике**: умеренно-рисковых клиентов модель
  часто относит к классу 0 — «ловит» только явные случаи. Это материал
  для дня 8 (другая модель/гиперпараметры).
