## 🐼 Что такое pandas

**pandas** — библиотека для работы с табличными данными в Python. Если
коротко: это «Excel внутри Python», но программный и быстрый. Основной
объект — **DataFrame**: таблица со строками и именованными столбцами, у
каждого столбца свой тип.

Зачем он в ML-сервисе: датасет `churn_dataset.csv` — это таблица из 2000
строк и 10 столбцов. pandas даёт читать её одной строкой, считать статистику,
фильтровать и преобразовывать — без ручных циклов по файлу.

> Под капотом числовые столбцы хранятся как массивы NumPy фиксированного
> типа — поэтому операции над целыми столбцами быстрые (векторизованы).

---

## 📥 Чтение CSV: `pd.read_csv`

```python
import pandas as pd
df = pd.read_csv(path)
```

`read_csv` сам:
- читает файл,
- берёт первую строку как **названия столбцов**,
- **определяет типы** каждого столбца (число/строка): `monthly_fee` станет
  `float64`, `support_requests` — `int64`, `region` — строкой (`object`).

Результат — `DataFrame`, который мы храним в поле `self.df` класса
`ChurnDataset`. Дальше работаем уже с ним, а не с файлом.

---

## 🔑 Объекты pandas: DataFrame и Series

- **DataFrame** — вся таблица. У него есть:
  - `df.shape` → кортеж `(строки, столбцы)`, напр. `(2000, 10)`;
  - `df.columns` → имена столбцов;
  - `df.head(n)` → первые `n` строк (тоже DataFrame).
- **Series** — один столбец (или строка). `df["churn"]` — это Series со
  значениями целевого признака.

В коде дня это используется так:

| Что нужно | Вызов pandas |
|-----------|--------------|
| число строк | `df.shape[0]` |
| число столбцов | `df.shape[1]` |
| имена признаков | `list(df.columns)` |
| распределение классов | `df["churn"].value_counts()` |
| первые n строк | `df.head(n)` |

---

## 📊 `value_counts()` — распределение по классам

```python
df["churn"].value_counts().sort_index()
# 0 -> 1597
# 1 -> 403
```

`value_counts()` берёт столбец и считает, сколько раз встречается каждое
значение. Для целевого `churn` это сразу даёт баланс классов: ~1597 клиентов
остались (0) и ~403 ушли (1). Классы несбалансированы (~20% оттока) — это
важно помнить при обучении модели в следующих днях.

`sort_index()` упорядочивает по самому значению (0, затем 1), чтобы вывод был
стабильным.

## 🔄 Мост pandas → Pydantic: `to_dict(orient="records")`

Самая интересная связка дня. По заданию строки датасета надо превратить в
объекты `DatasetRowChurn` (Pydantic-модель из дня 2). Делается так:

```python
records = df.head(n).to_dict(orient="records")
# -> [{'monthly_fee': 9.99, 'support_requests': 1, ..., 'churn': 1}, ...]
rows = [DatasetRowChurn(**row) for row in records]
```

- `to_dict(orient="records")` превращает таблицу в **список словарей**, по
  одному на строку, где ключи — имена столбцов.
- `DatasetRowChurn(**row)` распаковывает словарь в поля модели; Pydantic
  валидирует значения по типам (как в дне 2).

⚠️ **Тонкость с типами.** pandas хранит числа как `numpy.int64` /
`numpy.float64`, а не как обычные Python `int`/`float`. Pydantic v2 их
принимает и приводит к нативным типам, поэтому конвертация проходит без
ошибок — но это та деталь, которую стоило проверить (и мы проверили).

Так замыкаются дни 2 и 3: pandas читает таблицу, Pydantic гарантирует, что
каждая строка соответствует схеме.

## 🧩 Организация кода: зачем несколько модулей

Раньше всё жило в одном `main.py`. В дне 3 код разбит на три файла:

```
models.py   — Pydantic-модели (FeatureVectorChurn, DatasetRowChurn)
dataset.py  — класс ChurnDataset (работа с данными), импортирует models
main.py     — FastAPI-приложение, импортирует и dataset, и models
```

**Почему модели вынесены в `models.py`:** теперь их использует не только
`main.py`, но и `dataset.py`. Если бы модели остались в `main.py`, то
`dataset.py` импортировал бы из `main.py`, а `main.py` — из `dataset.py`.
Это **циклический импорт** — Python запутается, что грузить первым, и упадёт.
Отдельный нейтральный модуль `models.py`, от которого зависят оба, разрывает
цикл. Это типичный приём роста проекта: общие сущности выносят «вниз», чтобы
от них зависели остальные, а не наоборот.

## 📁 Надёжный путь к файлу: `pathlib.Path(__file__)`

CSV лежит в общей папке `data/` в корне проекта. Путь строим не от «текущей
папки» (она зависит от того, откуда запустили `uvicorn`), а от расположения
самого модуля:

```python
from pathlib import Path
DATA_PATH = Path(__file__).resolve().parents[2] / "data" / "churn_dataset.csv"
```

- `__file__` — путь к `dataset.py`;
- `.resolve()` — делает его абсолютным;
- `.parents[2]` — поднимается на 3 уровня: `3_day` → `homework` → корень;
- дальше дописываем `data/churn_dataset.csv`.

Так сервис найдёт датасет независимо от рабочей директории.
