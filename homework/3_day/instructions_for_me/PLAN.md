## ⚙️ Как будет работать решение

### Модуль `dataset.py` — класс `ChurnDataset`
- В конструкторе читает CSV через `pandas.read_csv` и хранит его как
  `DataFrame` (поле `self.df`).
- Путь к файлу вычисляется относительно расположения модуля
  (`Path(__file__).parents[2] / "data" / "churn_dataset.csv"`), поэтому не
  зависит от того, из какой папки запущен сервер.
- Методы:
  - `to_rows()` — преобразует **все** строки в объекты `DatasetRowChurn`
    (через Pydantic, с валидацией);
  - `preview(n)` — первые `n` строк как объекты `DatasetRowChurn`;
  - `info()` — словарь со сводкой: число строк, число столбцов, список
    признаков, распределение `churn` по классам.

### Эндпоинты в `main.py`
- `GET /dataset/preview?n=5` → первые `n` строк датасета в виде JSON.
- `GET /dataset/info` → сводная статистика по датасету.
- `GET /` и `POST /predict` — без изменений с дней 1–2.

Датасет загружается один раз при старте приложения
(`dataset = ChurnDataset()` на уровне модуля), а не на каждый запрос.

## ⚠️ Возможные подводные камни
- **Путь к CSV.** Если строить путь относительно текущей папки, сервер
  упадёт при запуске из другого каталога. Решаем через `Path(__file__)`.
- **numpy-типы.** `df.to_dict()` отдаёт `numpy.int64/float64`. Pydantic v2
  их принимает и приводит к нативным `int/float` — проверяем тестом.
- **Циклический импорт.** Поэтому модели — в отдельном `models.py`.
- **Ключи распределения** churn в JSON станут строками `"0"/"1"` (в JSON
  ключи всегда строки) — это нормально.
