# 🧰 Новые технологии дня 10 — глобальные обработчики исключений

До сегодня ошибки в сервисе жили сами по себе: Pydantic отвечал своим
форматом `{"detail": [...]}`, мы — своим `{"detail": "..."}` через
`HTTPException`, а sklearn вообще ронял запрос в 500 с трассировкой.
День 10 — про то, как перехватить всё это в одном месте.

Главная идея: **обработка ошибок — это не `try/except` в каждом
эндпоинте, а свойство приложения**.

---

## 🎣 app.exception_handler — перехват на уровне приложения

FastAPI (точнее, Starlette под ним) позволяет зарегистрировать функцию на
**тип исключения**:

```python
@app.exception_handler(ValueError)
def handle_data_error(request, exc):
    return error_response(400, "data_error", f"ошибка обработки данных: {exc}")
```

Дальше работает так: исключение из эндпоинта поднимается вверх, Starlette
берёт его класс и **идёт по цепочке наследования** (MRO), пока не найдёт
зарегистрированный обработчик. Поэтому:

- `ApiError` ловится обработчиком `HTTPException` — потому что он его
  наследник;
- `TypeError` из sklearn ловится своим обработчиком, а не общим
  `Exception`, — потому что точное совпадение находится раньше;
- обработчик `Exception` — последняя сеть: сюда падает всё, что никто не
  перехватил.

Плюс подхода: эндпоинт остаётся чистым. В дне 9 в `/model/train` был
`try/except (TypeError, ValueError)` — сегодня он **удалён**, а поведение
стало лучше: теперь так же аккуратно обрабатываются ошибки и в
`/predict`, и в любом эндпоинте, который появится завтра.

## ⚠️ Два разных HTTPException

Тонкость, на которой легко потерять час:

```python
from fastapi import HTTPException            # наследник starlette-версии
from starlette.exceptions import HTTPException  # базовый класс
```

Сам фреймворк, когда отдаёт 404 «нет такого маршрута» или 405 «не тот
метод», кидает **starlette-версию**. Если зарегистрировать обработчик на
`fastapi.HTTPException`, эти ответы пройдут мимо и вернутся в старом
формате `{"detail": "Not Found"}` — единый формат сломается там, где его
проще всего не заметить.

Поэтому обработчик регистрируем на starlette-класс — он ловит **и** его,
**и** всех наследников, включая наш `ApiError`.

## 🏷️ ApiError — исключение с машиночитаемым кодом

```python
class ApiError(HTTPException):
    def __init__(self, status_code: int, code: str, message: str):
        super().__init__(status_code=status_code, detail=message)
        self.code = code
```

Зачем вообще `code`, если есть HTTP-статус? Статусов мало и они грубые:
400 — это и «пустой датасет», и «sklearn не понял гиперпараметр». Клиенту
(или фронтенду) удобнее ветвиться по строке: `empty_dataset`,
`model_not_trained`, `data_error`. HTTP-код говорит **классу проблемы**,
`code` — **конкретной причине**.

Наследование от `HTTPException` — способ не плодить второй обработчик: у
чужих исключений поля `code` нет, поэтому берём его безопасно:

```python
getattr(exc, "code", "http_error")
```

## 🔢 Какой HTTP-код выбрать

| Код | Смысл | Наш случай |
|---|---|---|
| **400** Bad Request | запрос неправильный по сути | пустой датасет, sklearn не смог обработать данные |
| **409** Conflict | запрос корректен, но состояние сервиса не позволяет | предсказание до обучения модели |
| **422** Unprocessable Entity | синтаксис верный, содержимое не проходит валидацию | не тот тип, нет обязательного поля |
| **500** Internal Server Error | виноват сервер, а не клиент | непредвиденное исключение |

Ключевое различие 4xx/5xx: **4xx — «исправь запрос», 5xx — «исправь
сервер»**. Поэтому кривой гиперпараметр — 400 (это данные клиента), а не
500, хотя падает при этом библиотека.

Для «модель не обучена» день 9 отдавал 400; 409 точнее: с запросом всё в
порядке, проблема во времени — сначала `/model/train`.

## 📋 RequestValidationError — ошибки Pydantic в нашем формате

Валидацию входа по-прежнему целиком делает Pydantic (свои проверки типов
писать не нужно!). Меняется только **упаковка** результата: FastAPI кидает
`RequestValidationError`, мы его перехватываем и разворачиваем
`exc.errors()`:

```python
[{"type": "missing", "loc": ("body", "FeatureVectorChurn", "region"),
  "msg": "Field required", ...}]
```

- `loc` — «адрес» ошибки; первый элемент всегда источник (`body`, `query`,
  `path`), поэтому `loc[1:]` — это уже путь к полю;
- `msg` — человекочитаемое описание.

```python
{"field": ".".join(str(p) for p in e["loc"][1:]), "message": e["msg"]}
```

> Почему в ответе две записи вместо одной: тело `/predict` — union
> (`FeatureVectorChurn | list[FeatureVectorChurn]`), и Pydantic честно
> отчитывается, почему **не подошёл ни один** вариант. Отсюда префикс
> `FeatureVectorChurn.` в имени поля и дополнительная ошибка
> `list[FeatureVectorChurn]: Input should be a valid list`.

## 🕳️ Обработчик Exception — сеть под всеми остальными

```python
@app.exception_handler(Exception)
def handle_internal_error(request, exc):
    return error_response(500, "internal_error", "внутренняя ошибка сервиса")
```

Обратите внимание: в ответ **не** подставляется текст исключения. Это не
лень, а безопасность — трассировка и сообщения библиотек выдают наружу
пути к файлам, версии пакетов, иногда куски данных. Разработчику всё это
по-прежнему доступно: Starlette пишет полную трассировку в лог uvicorn.

Этот обработчик живёт не там, где остальные: обычные исключения ловит
`ExceptionMiddleware`, а необработанные — внешний `ServerErrorMiddleware`.
Практическое следствие: проверять его нужно живым запросом к запущенному
серверу.

## 📦 JSONResponse — ответ в обход модели ответа

Обработчик возвращает не словарь, а `JSONResponse`:

```python
JSONResponse(status_code=status_code, content={"error": {...}})
```

Обычный эндпоинт отдаёт словарь, а FastAPI сам сериализует его и ставит
код 200. В обработчике оба решения нужно принять самим — какой статус и
какое тело, — поэтому собираем ответ напрямую. Вся сборка живёт в одной
функции `error_response()`: формат ошибки описан в проекте ровно один раз.

---

## 📖 responses={...} — примеры ошибок в Swagger

OpenAPI знает только про успешный ответ (его FastAPI выводит из
аннотации). Ошибки нужно описать явно:

```python
@app.post("/predict", responses={
    409: error_example("model_not_trained", "модель ещё не обучена — вызовите POST /model/train"),
    422: error_example("validation_error", "некорректные входные данные"),
})
```

`error_example()` — маленькая обёртка над структурой OpenAPI
`{"content": {"application/json": {"example": {...}}}}`, чтобы не
дублировать её в каждом декораторе. В `/docs` у эндпоинта появляется
раздел Responses с примерами тел ошибок — документация для клиента без
единой строчки текста руками.

## 📦 Итог: что нового по сравнению с днём 9

| Технология / приём | Зачем |
|--------------------|-------|
| **`@app.exception_handler`** | обработка ошибок один раз на всё приложение |
| **starlette `HTTPException`** | ловит и наши ошибки, и 404/405 от фреймворка |
| **Наследование `ApiError`** | добавили `code`, не заводя второй обработчик |
| **`RequestValidationError`** | ошибки Pydantic в нашем формате `details` |
| **Обработчик `Exception`** | 500 без трассировки наружу |
| **`JSONResponse`** | статус и тело ответа задаются вручную |
| **`responses={...}`** | примеры ошибок в OpenAPI/Swagger |
| **Коды 400/409/422/500** | осмысленный выбор статуса под ситуацию |
| **Удалённый `try/except`** | локальную обработку заменил глобальный обработчик |
