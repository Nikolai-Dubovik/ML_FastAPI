# 🧰 Новые технологии дня 6 — joblib и персистентность модели

День 5 научил сервис обучать модель, но она жила только в оперативной
памяти: перезапуск — и всё заново. День 6 про **персистентность**:
сериализация pipeline на диск (joblib), загрузка при старте приложения и
состояние сервиса в глобальной структуре.

---

## 💾 Сериализация: что это и зачем

**Сериализация** — превращение живого Python-объекта (наш обученный
pipeline со всеми весами логрегрессии и статистиками скейлера) в байты,
которые можно записать в файл. **Десериализация** — обратный процесс.

Обученная модель = объект в памяти. Обучение стоит времени (а на больших
данных — очень дорого), поэтому стандартная практика ML: **обучил →
сохранил артефакт → загружаешь готовым**. В проде модель вообще часто
обучается в одном месте, а сервис предсказаний просто читает файл.

---

## 📦 joblib vs pickle

Оба сериализуют произвольные Python-объекты:

| | **pickle** | **joblib** |
|---|---|---|
| Откуда | стандартная библиотека | ставится с scikit-learn |
| Сильная сторона | универсальность | эффективен для объектов с большими numpy-массивами |
| Для sklearn-моделей | работает | **рекомендован документацией sklearn** |

Внутри sklearn-моделей — numpy-массивы (веса, статистики скейлера), и
joblib хранит их компактнее и быстрее. API зеркален pickle:

```python
import joblib

joblib.dump(bundle, path)      # объект → файл
bundle = joblib.load(path)     # файл → объект
```

> ⚠️ Обе технологии **не безопасны для чужих файлов**: `load` исполняет
> код при десериализации — загружать можно только свои файлы. И обе **не
> гарантируют совместимость между версиями sklearn**: сохранили в одной
> версии, загружаете в другой — может сломаться. Наш общий `.venv` решает
> это: модель сохраняется и загружается одним окружением.

## 🎁 Bundle: сохраняем не только модель

`/model/status` должен показывать не только «обучена ли», но и **когда** и
**с какими метриками**. Метрики считаются в момент обучения на тестовой
выборке — если сохранить только pipeline, они потеряются. Поэтому на диск
кладём словарь-бандл:

```python
bundle = {
    "pipeline": pipeline,        # обученный Pipeline целиком
    "trained_at": datetime.now(timezone.utc).isoformat(),
    "metrics": {"accuracy": ..., "f1": ...},
}
joblib.dump(bundle, MODEL_PATH)
```

Приём из дня 5 окупается: pipeline содержит и предобработку, и модель —
**один файл переносит всё**, отдельно сохранять скейлер/энкодер не нужно.

## ⏰ Timestamp в ISO-формате

```python
from datetime import datetime, timezone
datetime.now(timezone.utc).isoformat()
# '2026-07-09T12:34:56.789012+00:00'
```

- **ISO 8601** — стандартный текстовый формат даты-времени: однозначно
  парсится, сортируется как строка, нативно понимается JSON-клиентами;
- **`timezone.utc`** — время в UTC с явным смещением `+00:00`: сервис не
  зависит от таймзоны машины, а «наивное» время без зоны — источник багов.

## 🌍 Глобальное состояние приложения

У сервиса появляется **состояние**: текущая модель. Храним его в
переменной уровня модуля — так же, как день 3 хранит `dataset`:

```python
model_state: dict | None = load_churn_model()   # выполняется при старте
```

Модуль `main.py` исполняется один раз при запуске uvicorn — значит,
загрузка модели происходит ровно один раз при старте. Файла нет → `None`,
сервис работает, но `/model/status` отдаёт `is_trained: false`.

Тонкость — обновление из эндпоинта:

```python
@app.post("/model/train")
def train():
    global model_state          # без этого — локальная переменная!
    ...
    model_state = save_churn_model(pipeline, metrics)
```

Без `global` Python создаст локальную переменную внутри функции, а
глобальная останется старой — классическая ловушка.

> Альтернатива module-level кода — **lifespan** (события старта/остановки
> FastAPI): загрузку можно повесить на старт приложения явно. Для нашего
> размера проекта достаточно уровня модуля; lifespan пригодится в дне 13.

## 🔗 Где это в API

- `POST /model/train` — после обучения сохраняет bundle на диск и в
  `model_state`; модель «выживает» между запросами и перезапусками;
- `GET /model/status` — читает `model_state` и отдаёт
  `is_trained` / `trained_at` / `metrics`. GET — потому что только
  **читает** состояние, ничего не меняя (в отличие от POST /model/train).

Проверка дня: train → рестарт uvicorn → `/model/status` показывает ту же
модель с тем же `trained_at`.

| Технология / приём | Зачем |
|--------------------|-------|
| **Сериализация** | сохранить обученный объект между запусками |
| **joblib** (`dump`/`load`) | эффективное хранение sklearn-моделей |
| **Bundle-словарь** | модель + время обучения + метрики в одном файле |

| **`global` в эндпоинте** | обновить состояние из функции-обработчика |
| **Артефакты вне git** | бинарные генерируемые файлы — в .gitignore |
