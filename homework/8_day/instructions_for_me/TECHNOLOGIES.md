# 🧰 Новые технологии дня 8 — RandomForest, Literal и конфигурируемое обучение

До сих пор модель была зашита в код: LogisticRegression и точка. День 8
превращает обучение в **конфигурируемый сервис**: тип модели и
гиперпараметры приходят в теле запроса.

---

## 🌲 RandomForestClassifier — вторая модель

**Случайный лес** — ансамбль из множества решающих деревьев: каждое дерево
обучается на случайной подвыборке данных и признаков, итог — голосование
деревьев.

Чем отличается от логистической регрессии:

| | LogisticRegression | RandomForestClassifier |
|---|---|---|
| Тип зависимости | линейная | нелинейная, взаимодействия признаков |
| Масштабирование | важно | безразлично (но в общем pipeline не мешает) |
| Интерпретация | веса признаков | важности признаков |
| Скорость | быстрее | медленнее (сотни деревьев) |

На наших данных лес поднял f1 с 0.045 до 0.175 при той же accuracy —
поймал нелинейные паттерны оттока.

Ходовые гиперпараметры: `n_estimators` (число деревьев), `max_depth`
(глубина), `class_weight="balanced"` (борьба с дисбалансом).

## 🔒 Literal — enum-валидация в Pydantic

```python
model_type: Literal["logreg", "random_forest"] = "logreg"
```

`Literal` — тип «строго одно из перечисленных значений». Pydantic сам
отклонит `"boosting"` с ошибкой 422 и понятным сообщением, а в /docs
покажет выпадающий список допустимых значений. Валидация «какие модели мы
умеем» живёт в схеме, а не в if-ах эндпоинта.

---

## 🏭 default_factory — дефолт для изменяемых типов

```python
hyperparameters: dict = Field(default_factory=dict)
```

Изменяемый дефолт (`= {}`) — классическая ловушка Python: один и тот же
словарь разделялся бы между всеми объектами. `default_factory=dict`
создаёт **новый** пустой словарь для каждого экземпляра.

А дефолты обоих полей вместе позволяют объявить весь конфиг опциональным:

```python
def model_train(config: TrainingConfigChurn = TrainingConfigChurn()):
```

POST без тела → конфиг с дефолтами → поведение дней 5–7 не сломано.
Обратная совместимость API — хорошая привычка.

## 📦 ** — распаковка гиперпараметров

Гиперпараметры приходят словарём, а конструктору модели нужны именованные
аргументы. Мост между ними — оператор распаковки `**`:

```python
hp = {"class_weight": "balanced", "C": 0.5}
LogisticRegression(max_iter=1000, **hp)
# то же самое, что LogisticRegression(max_iter=1000, class_weight="balanced", C=0.5)
```

Наши дефолты (`max_iter=1000`, у леса `random_state=42`) стоят **до**
распаковки — пользователь может их переопределить своим значением.
Несуществующее имя параметра sklearn отвергает `TypeError`-ом — в
эндпоинте это превращается в честный 400.

## 🗃️ Выбор модели по типу

```python
def build_model(model_type: str, hyperparameters: dict):
    if model_type == "logreg":
        return LogisticRegression(max_iter=1000, **hyperparameters)
    if model_type == "random_forest":
        return RandomForestClassifier(random_state=42, **hyperparameters)
    raise ValueError(...)
```

Ключевой архитектурный момент: **меняется только классификатор, pipeline
один и тот же** — ColumnTransformer с предобработкой не дублируется.
Добавить третью модель = добавить одну ветку в `build_model`.

## ⚠️ protected_namespaces — ловушка Pydantic v2

Pydantic v2 резервирует префикс `model_` для своих методов
(`model_dump`, `model_config`...). Поле `model_type` вызывает
предупреждение о конфликте. Решение — отключить защиту namespace в
конкретной модели:

```python
class TrainingConfigChurn(BaseModel):
    model_config = ConfigDict(protected_namespaces=())
    model_type: Literal["logreg", "random_forest"] = "logreg"
```

## 📊 Конфигурация как часть артефакта

Bundle пополняется полями `model_type` и `hyperparameters`. Смысл: метрики
без конфигурации бессмысленны — «f1 = 0.35» ничего не говорит, пока не
знаешь, **какая модель и с какими параметрами** его дала. Теперь
`/model/status` отвечает на вопрос «что за модель сейчас в проде»
полностью. Это первый шаг к экспериментам: сравнение конфигураций (таблица
в README) — ровно то, что в день 11 станет историей обучений.
