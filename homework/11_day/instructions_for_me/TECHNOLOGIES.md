## 📈 ROC-AUC — метрика для несбалансированных классов

`accuracy` обманчива, когда классы несбалансированы. У нас ~80% клиентов
остаются: модель, всегда предсказывающая «останется», получит accuracy ≈ 0.80,
не поймав **ни одного** уходящего. Именно поэтому у logreg accuracy 0.7875 при
почти нулевом f1 0.0449 — она почти никого не относит к оттоку.

**ROC-AUC** смотрит на ранжирование по вероятности, а не на решения при
пороге 0.5:
- считается по `predict_proba` (вероятность класса 1), а не по `predict`;
- 0.5 — как случайное угадывание, 1.0 — идеальное разделение;
- не зависит от выбранного порога и от дисбаланса.

```python
from sklearn.metrics import roc_auc_score
proba = pipeline.predict_proba(X_test)[:, 1]   # вероятность оттока
roc_auc = round(float(roc_auc_score(y_test, proba)), 4)
```
`predict_proba` возвращает матрицу `[P(0), P(1)]` по строкам; `[:, 1]` — это
столбец вероятностей положительного класса. У нас logreg → 0.6091, лес по
умолчанию → 0.5881: обе слабоваты, но roc_auc честно это показывает, тогда как
accuracy у обеих одинаковая (0.7875) и вводит в заблуждение.

## 🗄️ Персистентная история на JSON

Модель мы уже храним в joblib. Историю обучений удобно держать в **JSON** —
человекочитаемо и легко читается любым клиентом:
```python
import json
from pathlib import Path

HISTORY_PATH = Path(__file__).resolve().parent / "models" / "training_history.json"

def load_history() -> list[dict]:
    if not HISTORY_PATH.exists():
        return []
    return json.loads(HISTORY_PATH.read_text(encoding="utf-8"))

def append_record(record: dict) -> None:
    history = load_history()
    history.append(record)
    HISTORY_PATH.parent.mkdir(parents=True, exist_ok=True)
    HISTORY_PATH.write_text(json.dumps(history, ensure_ascii=False, indent=2),
                            encoding="utf-8")
```
Ключевой момент — **read-modify-write**: прочитать текущий список, добавить
запись, записать целиком назад. Если просто перезаписывать, история затрётся.
`ensure_ascii=False` — чтобы русские строки не превращались в `\uXXXX`.

> Почему файл, а не переменная в памяти? Чтобы история **пережила рестарт**.
> Тот же принцип, что с моделью: перезапустил uvicorn — данные на месте.

## 🧾 Что такое «запись обучения»

Одна запись фиксирует эксперимент целиком — по ней потом можно понять, «что
за модель и насколько хороша»:
```json
{"timestamp": "2026-07-30T...Z", "model_type": "random_forest",
 "hyperparameters": {"n_estimators": 200, "max_depth": 5},
 "metrics": {"accuracy": 0.7975, "f1": 0.0471, "roc_auc": 0.6243}}
```
`timestamp` берём из bundle (`trained_at`, ISO-8601 в UTC — уже есть с дня 6).
Гиперпараметры и метрики — рядом, поэтому историю можно читать как таблицу
экспериментов.

## 🔎 Фильтрация через query-параметры

`GET /model/metrics` принимает необязательные параметры — FastAPI сам
превращает аргументы функции в query-строку:
```python
@app.get("/model/metrics")
def model_metrics(model_type: str | None = None, limit: int = 5):
    history = load_history()
    if model_type:
        history = [r for r in history if r["model_type"] == model_type]
    return {"last": history[-1] if history else None,
            "history": history[-limit:]}
```
- `model_type=None` по умолчанию → фильтр не применяется;
- `history[-limit:]` — последние `limit` записей (срез с конца);
- `last` — самое свежее обучение (или `None`, если ещё не обучали).

Так один эндпоинт закрывает и «метрики последнего обучения», и «список
последних записей», и «фильтр по типу модели».

## ⚖️ Зачем это: сравнение настроек

Смысл истории — **сравнивать эксперименты**. На наших данных:

| Модель | accuracy | f1 | roc_auc |
|--------|----------|------|---------|
| logreg (по умолч.) | 0.7875 | 0.0449 | 0.6091 |
| random_forest (по умолч.) | 0.7875 | **0.1748** | 0.5881 |
| random_forest (200 / depth 5) | **0.7975** | 0.0471 | **0.6243** |

Одна метрика не даёт полной картины: по f1 лучше лес по умолчанию, по roc_auc —
настроенный лес. История держит эти прогоны рядом, чтобы выбор настроек был
осознанным, а не «на глаз».
