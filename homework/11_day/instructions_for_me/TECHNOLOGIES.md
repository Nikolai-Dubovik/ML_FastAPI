## 📈 ROC AUC — метрика для несбалансированных классов

### Чем плоха accuracy на наших данных

В датасете ~20% оттока. Модель, которая **всем** ставит «останется», без
единой попытки что-то предсказать получает accuracy 0.80. Наши модели дают
0.7875 — то есть почти неотличимо от «глупой» константы. По одной accuracy
невозможно понять, есть ли в модели польза.

`f1` честнее (0.0449 у логрегрессии — плохо), но зависит от **порога**:
класс назначается по правилу «вероятность > 0.5». Модель может неплохо
оценивать риск, но не дотягивать до 0.5 ни на одном клиенте — и f1 будет
почти нулевым.

### Что измеряет ROC AUC

`roc_auc` смотрит не на метки, а на **вероятности**, и отвечает на вопрос:

> если взять случайного ушедшего клиента и случайного оставшегося — с
> какой вероятностью модель даст первому балл риска выше?

- **0.5** — модель не отличает классы (случайное угадывание);
- **1.0** — идеальное ранжирование;
- **0.6091** (наша логрегрессия) — слабый, но не нулевой сигнал.

Ключевое свойство: метрика **не зависит от порога**. Даже если 0.5 —
неудачная граница, ROC AUC покажет, есть ли в вероятностях полезный
порядок. Отсюда и практический смысл для бизнеса: можно взять топ-100
клиентов по риску и позвонить им — для такого сценария важен порядок, а не
метки.

### Как считать — главная ловушка дня

```python
y_proba = pipeline.predict_proba(X_test)[:, 1]   # вероятность класса «уйдёт»
roc_auc_score(y_test, y_proba)
```

`predict_proba` возвращает матрицу `(n_объектов, n_классов)`; столбец с
индексом 1 — вероятность положительного класса (порядок задан
`pipeline.classes_`, у нас `[0, 1]`).

Если по ошибке передать метки `y_pred` вместо вероятностей, `roc_auc_score`
**не упадёт** — посчитает по двум точкам вместо кривой и вернёт заниженное
число. Ошибка тихая, поэтому её стоит помнить.

## 📓 Журнал экспериментов — зачем и в каком виде

`storage.py` хранит **одну** модель — последнюю; каждое обучение затирает
предыдущую. Значит, вопрос «а что получилось у random forest полчаса
назад?» ответа не имел.

Журнал (`history.py`) решает это: он хранит **все запуски**, но без самих
моделей — только метаданные:

```json
{"trained_at": "...", "model_type": "random_forest",
 "hyperparameters": {"n_estimators": 300, "max_depth": 5},
 "metrics": {"accuracy": 0.8, "f1": 0.0698, "roc_auc": 0.6196, ...}}
```

Важно, что записываются **и гиперпараметры, и метрики**: метрика без
конфигурации бесполезна — непонятно, что именно её дало.

В индустрии этим занимаются MLflow, Weights & Biases и подобные системы
трекинга экспериментов. Наш JSON-файл — их суть в 20 строках: воспроизводимая
связка «настройки → результат → время».

## 💾 JSON-файл вместо памяти

Задание разрешает хранить историю «в памяти или в простом JSON файле».
Выбран файл, и вот почему: список в памяти живёт до перезапуска uvicorn, а
`--reload` перезапускает процесс при каждой правке кода — история исчезала
бы по десять раз за вечер.

```python
def load_history(path: Path = HISTORY_PATH) -> list[dict]:
    if not path.exists():
        return []
    return json.loads(path.read_text(encoding="utf-8"))

def append_record(record: dict, path: Path = HISTORY_PATH) -> None:
    history = load_history(path)
    history.append(record)
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(json.dumps(history, ensure_ascii=False, indent=2), encoding="utf-8")
```

Приёмы, которые тут стоит заметить:

- **read-modify-write** — файл читается целиком, дописывается запись, файл
  пишется обратно. Для тысяч записей это было бы расточительно (там нужен
  формат вроде JSON Lines или база), для учебного журнала — самый простой
  рабочий вариант;
- **«нет файла» — не ошибка,** а пустая история: `return []` вместо
  исключения. Первый запуск сервиса должен работать без подготовки;
- **`ensure_ascii=False`** — кириллица в файле остаётся читаемой
  (`"отток"`), а не превращается в
  `"\u043e\u0442\u0442\u043e\u043a"`;
- **`indent=2`** — журнал читается глазами: `cat models/training_history.json`;
- **JSON-сериализуемость.** В запись попадают только простые типы. Метрики
  уже приведены к `float`/`int` — numpy-типы (`np.float64`) `json` писать не
  умеет и падает с `TypeError`.

### Два файла в `models/` — и это не дубль

```
models/
├── churn_model.joblib        ← артефакт: pipeline + метаданные (перезаписывается)
└── training_history.json     ← журнал: все запуски (только дописывается)
```

Разделение намеренное: артефакт отвечает на вопрос «чем предсказывать
прямо сейчас», журнал — «что мы уже пробовали». Обучение перезаписывает
первый и **дополняет** второй.

## 🔎 Query-параметры фильтрации

```python
def model_metrics(limit: int = 5, model_type: str | None = None):
```

Аргументы функции-эндпоинта, которых нет в пути, FastAPI автоматически
считает **query-параметрами**: `/model/metrics?limit=1&model_type=logreg`.
Значения по умолчанию делают их необязательными, а `str | None = None` —
«параметр может отсутствовать».

Порядок операций важен:

```python
if model_type:
    history = [record for record in history if record["model_type"] == model_type]
return {"last": history[-1], "history": history[-limit:]}
```

Сначала фильтр, потом срез. Наоборот — «последние 5 записей, из них
random_forest» — вернуло бы меньше записей, чем есть, и пользователь решил
бы, что история потерялась. Это классическая ошибка `filter` после `limit`,
знакомая по SQL: `WHERE` работает раньше `LIMIT`.

## 📦 Итог: что нового по сравнению с днём 10

| Технология / приём | Зачем |
|--------------------|-------|
| **`roc_auc_score`** | метрика, не обманывающаяся дисбалансом классов |
| **`predict_proba(...)[:, 1]`** | ROC AUC считается по вероятностям, не по меткам |
| **Журнал экспериментов** | сравнение конфигураций по записям, а не по памяти |
| **JSON-файл как хранилище** | история переживает перезапуск и `--reload` |
| **read-modify-write** | простейший способ дописать запись в JSON-список |
| **`ensure_ascii=False`, `indent=2`** | журнал читается человеком |
| **Query-параметры `limit` / `model_type`** | необязательные фильтры без новых моделей |
| **Фильтр раньше среза** | иначе часть записей теряется молча |
